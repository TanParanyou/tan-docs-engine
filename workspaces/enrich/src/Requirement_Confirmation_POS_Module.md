## ส่วนที่ 2: นิยามคำศัพท์ที่ใช้ร่วมกัน (Glossary & Definitions)
* **Order / Invoice**: รายการสั่งซื้อบริการหรือสินค้าหน้าร้านของลูกค้า
* **Primary Stylist & Assistant**: ช่างผู้ให้บริการหลัก (จำกัด 1 คนต่อรายการบริการ) และช่างผู้ช่วย

### 4.1 REQ-POS-001 — เบิกสินค้า/วัตถุดิบเข้า Order และกำหนดการแสดงในใบเสร็จ

**Requirement จากการประชุม**  
พนักงานสามารถเบิกสินค้าหรือวัตถุดิบเคมี (เช่น สีทำผม, ยายืด) เข้า Order ของลูกค้าได้ โดยสามารถเลือกกำหนดได้ว่ารายการนั้นจะให้แสดงหรือซ่อนในใบเสร็จของลูกค้า

**พฤติกรรมที่คาดหวัง**

1. สามารถตั้งค่าเริ่มต้น (Default) ที่ตัวสินค้าได้ว่าจะแสดงหรือไม่แสดงในใบเสร็จ
2. พนักงานหน้าร้านสามารถปรับเปลี่ยนตัวเลือก แสดง/ซ่อน รายการวัตถุดิบใน Order เป็นรายครั้งได้
3. รายการวัตถุดิบที่ไม่แสดงในใบเสร็จ ยังคงตัดสต๊อกตาม Lot ที่เลือกและเก็บบันทึกประวัติในระบบอย่างถูกต้อง
4. รายการวัตถุดิบเคมีที่ซ่อน จะไม่นำมูลค่าไปคิดคำนวณเงินกับลูกค้า (เว้นแต่จะกำหนดราคาขายเพิ่มเติม)

**ตัวอย่างการยอมรับ**  
ช่างทำสีผมให้ลูกค้า คีย์เบิกสีหลอด A เข้า Order -> เลือก "ซ่อนในใบเสร็จ" -> ในใบเสร็จลูกค้าขึ้นเฉพาะค่าบริการ "Hair Color 3,500 บาท" แต่สต๊อกสีหลอด A ถูกตัดออกจากระบบเรียบร้อย

**ต้องยืนยันเพิ่มเติม**

- สิทธิ์การเปลี่ยนตัวเลือกแสดง/ซ่อน: `[ ] พนักงานทุกคน` `[ ] เฉพาะ Manager/Admin`
- หากวัตถุดิบเบิกเกินปริมาณมาตรฐาน อนุญาตให้คิดเงินเพิ่มในบิลลูกค้าหรือไม่: `[ ] ได้` `[ ] ไม่ได้`

**ผลการพิจารณา:** `[ ] ยืนยัน` `[ ] ขอแก้ไข` `[ ] ยังไม่อยู่ในขอบเขต` `[ ] ต้องหารือเพิ่มเติม`

### 4.2 REQ-POS-002 — บันทึกสูตรและผลการผสมสีใน Order (Consult Sheet)

**Requirement จากการประชุม**  
Order ต้องมีพื้นที่สำหรับบันทึกข้อมูลสูตรผสมสี ปริมาณ หน่วย Lot และหมายเหตุเคมีที่ใช้จริง เพื่อเก็บเป็นประวัติให้ช่างใช้ดูย้อนหลังสำหรับการให้บริการครั้งถัดไป

**พฤติกรรมที่คาดหวัง**

1. บันทึกสูตรสีในระดับรายการบริการของ Order โดยระบุชื่อสี ปริมาณ (ml/g) และเลข Lot
2. รองรับการบันทึกสูตรที่วางแผนไว้ (Planned Formula) และปริมาณที่ใช้จริง (Actual Formula)
3. ระบบบันทึกชื่อผู้บันทึก/แก้ไข และวันเวลาที่อัปเดตล่าสุด
4. ช่างสามารถเปิดดูประวัติสูตรสีเดิมย้อนหลังจากประวัติลูกค้าในหน้า CRM หรือ POS ได้

**ตัวอย่างการยอมรับ**  
ช่างเปิด Order บริการทำสี -> บันทึกสูตร "L'Oreal 8.11 ปริมาณ 60g + Developer 6% ปริมาณ 60g Lot L002" -> บันทึกสำเร็จ -> ครั้งถัดไปลูกค้ามาทำสี ช่างเปิดดูประวัติสูตรสีเดิมได้ทันที

**ต้องยืนยันเพิ่มเติม**

- ใครมีสิทธิ์บันทึกสูตรสี: `[ ] ช่างผู้ให้บริการ` `[ ] Cashier` `[ ] ทุก Role`
- ปริมาณเคมีที่กรอกในสูตรสี ให้ตัดสต๊อกอัตโนมัติหรือใช้บันทึกเป็นข้อมูลอย่างเดียว: `[ ] ตัดสต๊อกอัตโนมัติ` `[ ] บันทึกข้อมูลอย่างเดียว`

**ผลการพิจารณา:** `[ ] ยืนยัน` `[ ] ขอแก้ไข` `[ ] ยังไม่อยู่ในขอบเขต` `[ ] ต้องหารือเพิ่มเติม`

### 4.3 REQ-POS-003 — ระบุช่างหลัก ช่างผู้ช่วย และบริการใน POS

**Requirement จากการประชุม**  
ในรายการบริการของ POS ต้องระบุช่างผู้ให้บริการหลัก 1 คน และสามารถระบุช่างผู้ช่วยได้ เพื่อบันทึกประวัติการทำงานและเตรียมไว้รองรับการคำนวณค่าคอมมิชชัน

**พฤติกรรมที่คาดหวัง**

1. บริการแต่ละรายการใน Order ต้องบังคับระบุช่างหลัก 1 คน
2. สามารถเพิ่มช่างผู้ช่วย (Assistant) ในรายการบริการนั้นได้มากกว่า 1 คน
3. Order หนึ่งรายการที่มีหลายบริการ สามารถเลือกช่างหลักและผู้ช่วยต่างกันในแต่ละรายการบริการได้
4. ข้อมูลช่างถูกบันทึกไว้เพื่อดูรายงานประวัติการทำงาน และรองรับการคำนวณค่าคอมมิชชันในอนาคต

**ตัวอย่างการยอมรับ**  
ลูกค้าทำสี + ไดร์ผม -> รายการทำสีเลือก ช่างกฤต (ช่างหลัก) + ช่างอาร์ท (ผู้ช่วย) -> รายการไดร์ผมเลือก ช่างทิว (ช่างหลัก) -> ระบบบันทึกแยกช่างและแสดงในใบเสร็จตามที่กำหนด

**ต้องยืนยันเพิ่มเติม**

- ต้องการให้แสดงชื่อช่างในใบเสร็จของลูกค้าหรือไม่: `[ ] แสดงช่างหลัก` `[ ] แสดงทั้งช่างหลักและผู้ช่วย` `[ ] ไม่แสดง`
- การแบ่งสัดส่วนค่าคอมมิชชันระหว่างช่างหลักและผู้ช่วย: `[ ] หารเท่า` `[ ] กำหนดเปอร์เซ็นต์ต่างกัน`

**ผลการพิจารณา:** `[ ] ยืนยัน` `[ ] ขอแก้ไข` `[ ] ยังไม่อยู่ในขอบเขต` `[ ] ต้องหารือเพิ่มเติม`

### 4.4 REQ-POS-004 — จำกัดข้อมูลส่วนบุคคลของลูกค้าที่ช่างมองเห็น (PDPA)

**Requirement จากการประชุม**  
ผู้ใช้งานบทบาทช่าง (Stylist) ต้องมองไม่เห็นข้อมูลส่วนบุคคลที่ไม่จำเป็นของลูกค้า โดยให้ซ่อนเบอร์โทรศัพท์ออกจากหน้าปฏิทินนัดหมายและหน้างานของช่าง

**พฤติกรรมที่คาดหวัง**

1. หน้าตารางนัดหมายและหน้างานของบทบาทช่าง จะถูกซ่อนเบอร์โทรศัพท์ลูกค้า (แสดงเฉพาะ ชื่อ-ชื่อเล่น)
2. สิทธิ์การมองเห็นข้อมูลถูกควบคุมในระดับสิทธิ์ผู้ใช้งาน (Role-based Security)
3. ช่างยังคงมองเห็นข้อมูลที่จำเป็นต่อการทำงาน เช่น ชื่อลูกค้า, ประวัติบริการ, สูตรสี และรูปภาพ Before/After

**ตัวอย่างการยอมรับ**  
ช่างล็อกอินเข้าดูหน้าปฏิทินงาน -> เห็นชื่อลูกค้า "คุณกฤต (ซอย+ทำสี) 14:00 น." แต่ไม่เห็นเบอร์โทรศัพท์ -> ขณะที่แอดมิน/Cashier ล็อกอินจะเห็นเบอร์โทรศัพท์ "081-XXX-XXXX" ครบถ้วน

**ต้องยืนยันเพิ่มเติม**

- กรณีฉุกเฉินที่ช่างต้องติดต่อลูกค้า อนุญาตให้ดูเบอร์ได้หรือไม่: `[ ] ไม่อนุญาต (ต้องผ่านแอดมินเท่านั้น)` `[ ] อนุญาตแต่ต้องกด Override`

### 4.5 REQ-PKG-004 — การจองตัดสิทธิ์ Course ใน Order ก่อนชำระเงิน

**Requirement จากการประชุม**  
พนักงานสามารถเลือกตัดสิทธิ์คอร์สบริการ (Course) ใน Order ก่อนชำระเงิน โดยระบบจะเปลี่ยนสถานะสิทธิ์เป็น "Reserved" และจะตัดสิทธิ์ถาวรเมื่อปิด Order สำเร็จ

**พฤติกรรมที่คาดหวัง**

1. เมื่อเลือกตัด Course ใน Order สิทธิ์นั้นจะถูกเปลี่ยนสถานะเป็น จองไว้ (Reserved) ทันที
2. สิทธิ์ที่อยู่ในสถานะ Reserved จะไม่สามารถถูกนำไปเลือกใช้ซ้ำใน Order อื่นได้
3. เมื่อกรอกรหัส OTP ยืนยัน และปิด Order ชำระเงินสำเร็จ ระบบเปลี่ยนสถานะสิทธิ์เป็น ใช้แล้ว (Used)
4. หากมีการยกเลิก Order สิทธิ์ที่ Reserved อยู่จะถูกคืนกลับเป็น พร้อมใช้งาน (Available) อัตโนมัติ

**ตัวอย่างการยอมรับ**  
ลูกค้าเลือกใช้คอร์สทรีตเมนต์ (คงเหลือ 3 ครั้ง) -> พนักงานคีย์ลง Order -> สิทธิ์เหลือ 2 ครั้ง (Reserved 1) -> หากกดยกเลิก Order -> สิทธิ์กลับมาเป็น 3 ครั้งตามเดิม

**ต้องยืนยันเพิ่มเติม**

- กรณี Order ค้างข้ามวันโดยไม่ปิดบิล ให้ระบบยกเลิกการ Reserved อัตโนมัติหรือไม่: `[ ] ยกเลิกอัตโนมัติเมื่อสิ้นวัน` `[ ] ให้ค้างไว้จนกว่าจะกดยกเลิก`

**ผลการพิจารณา:** `[ ] ยืนยัน` `[ ] ขอแก้ไข` `[ ] ยังไม่อยู่ในขอบเขต` `[ ] ต้องหารือเพิ่มเติม`

### 4.6 REQ-INV-005 — เลือก Pop-up Lot วัตถุดิบ/สินค้าตอนขายหรือเบิกเข้า Order

**Requirement จากการประชุม**  
หากสินค้าหรือวัตถุดิบเคมีมีสต๊อกมากกว่าหนึ่ง Lot ระบบจะ Pop-up ให้พนักงานเลือก Lot ที่ต้องการตัดตอนขายหรือเบิกเข้า Order

**พฤติกรรมที่คาดหวัง**

1. แสดงรายการ Lot ที่มีคงเหลือในสาขา พร้อมเลข Lot, ยอดคงเหลือ, วันผลิต และวันหมดอายุ
2. ระบบแนะนำ Lot ที่ใกล้หมดอายุก่อนตามหลัก FEFO แต่ผู้ใช้งานเลือกเปลี่ยน Lot อื่นได้
3. สามารถเลือกตัดหลาย Lot รวมกันได้เมื่อ Lot เดียวมีจำนวนไม่เพียงพอ
4. ระบบไม่อนุญาตให้ตัดเกินยอดคงเหลือจริงของ Lot นั้นๆ

**ตัวอย่างการยอมรับ**  
ช่างเบิกแชมพู 2 ขวด -> ระบบ Pop-up มี Lot A (หมดอายุ ต.ค.) เหลือ 1 ขวด และ Lot B (หมดอายุ ธ.ค.) เหลือ 5 ขวด -> ระบบแนะนำตัด Lot A 1 ขวด + Lot B 1 ขวด -> ช่างยืนยันตัดสต๊อก
